## Trust and verification

*Provenance:* controller live-tested on staging DB (`samparka-staging`, DB `test`) with real POS tokens. A real `curl` returns a live `short_url` (`/r/...`) that 302s to the correct `wa.me` link. Idempotency demonstrated: same request twice → same `qr_link`, one session in `purchasesessions`.

## Automated tests

`__tests__/integrations/pos.purchase-qr.test.js` (9 passed, 3 required companion suites also passed):

| Test | Assertion |
|---|---|
| happy path | 200 with `qr_link`, `purchase_reference = posqr:{provider}:...`, amount |
| persistence | session in `purchasesessions` with `QR_GENERATED`, `communication.metadata.short_url` |
| idempotency | same request twice → same `qr_link`, count stays 1 |
| missing/invalid items | 400 |
| missing/negative amount | 400 |
| unknown token | 401 |
| unknown provider | 404 |
| POS connected, no comm provider | 422 (`no active connected communication provider`) — no session created |
| POS not connected (status CREATED) | 409 `pos_not_connected` — no session created |

Existing companion suites still pass: `body.size.test.js` (4/4), `contract.responses.test.js` (8/8), `location-resolution.test.js` (4/4). Run them lean to avoid the VS Code OOM:

```bash
NODE_OPTIONS="--max-old-space-size=512" npx jest __tests__/integrations/pos.purchase-qr.test.js --runInBand
```

## Deployment notes

* All backend. No frontend deploy required (except `checkitbro` if you keep it).
* `checkitbro` (`src/pages/CheckItBro.jsx`, `checkitbroDebugController.js`, the `/checkitbro/debug` route on `purchaseSessions/routes.js`) is **localhost-only**. Remove those 3 additions before cutting a production release. Remove the comment-guarded `CheckItBro` import + `/checkitbro` route in `MainApp.jsx` at the same time.
* The staging `SERVER_URL` currently produces `http://localhost:8081/r/...` short URLs — in production `SERVER_URL` yields `https://samparka.co/r/...` automatically via `RedirectLinkService.baseUrl`.
* The `posqr:` prefix never collides with dashboard references (`ps_…`).
