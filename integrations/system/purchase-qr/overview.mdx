The Purchase QR endpoint lets **System terminals** create a Samparka *purchase-checkout* session on the fly and receive the QR link in the same HTTP response. The System renders that link as a QR and prints it on its receipt. The customer scans → WhatsApp flow → Wapio verification → points. The endpoint reuses 100% of the existing purchase-checkout pipeline — no new models, no new loyalty logic, no new QR infrastructure.

<Info>
  The **Communication** feature requires a connected WhatsApp communication provider. To use this feature and get access, contact the Samparka team.
</Info>

```mermaid
sequenceDiagram
  participant System as System
  participant SAM as Samparka
  participant CUST as Customer

  System->>SAM: POST { integrationKey, payload: { event_type, order_id, amount, currency, items } }
  SAM->>SAM: Create purchase-checkout session
  SAM->>SAM: Wapio signs the QR
  SAM-->>System: { qr_link }
  System->>System: Render link as QR and print on receipt
  CUST->>CUST: Scans QR on receipt
  CUST->>SAM: Opens WhatsApp deep link & claims
  SAM->>SAM: Verification + completion orchestrator
  SAM-->>CUST: Points awarded
```

## Why this endpoint and not the existing alternatives

| Existing path | What it does | Why not enough |
|---|---|---|
| Dashboard checkout (`POST /api/v1/purchase-sessions`) | Staff manually types amount → QR on screen | Requires Samparka dashboard; System cashiers never open it |
| System webhooks (`POST /integrations/system/:provider/events`) | System pushes `sale.completed` → direct points, no QR | Gives no QR to print |
| Canonical ingress (`POST /api/v1/integrations/purchases`) | Purchase sessions push *completed* purchases into the canonical `InternalEvent` pipeline | That's the sink after completion, not the source that creates QR sessions |

The new route is the **missing source**: System *creates* the QR session instead of staff.

## State and lifecycle

```mermaid
stateDiagram-v2
  [*] --> CREATED
  CREATED --> QR_GENERATED: ensureQrGenerated
  QR_GENERATED --> WAITING_FOR_CUSTOMER_CLAIM: customer waits
  WAITING_FOR_CUSTOMER_CLAIM --> CLAIMED: customer scans
  CLAIMED --> POINTS_AWARDED
  POINTS_AWARDED --> COMPLETED
  COMPLETED --> [*]
  QR_GENERATED --> QR_GENERATED: System retry while pending (same QR, 200)
  WAITING_FOR_CUSTOMER_CLAIM --> WAITING_FOR_CUSTOMER_CLAIM: System retry while pending (same QR, 200)
```

Statuses that still return the same QR (retry-safe): `QR_GENERATED`, `WAITING_FOR_CUSTOMER_CLAIM`. Terminal/expired ones return `409 purchase_qr_unavailable`/`410 purchase_qr_expired`.

<Info>
  **Golden rule:** Loyalty QR failure must never block or fail the sale. Always print the receipt.
</Info>

## End-to-end sequence (including the customer scan)

```mermaid
sequenceDiagram
  participant System as System
  participant CTL as purchaseQrController
  participant SVC as PurchaseSessionService
  participant WAPIO as Wapio
  participant RDL as RedirectLinkService
  participant CUST as Customer
  participant WHATS as WhatsApp
  participant ORCH as CompletionOrchestrator
  participant ING as Canonical Ingress

  System->>CTL: POST { integrationKey, payload: { event_type, order_id, amount, items } }
  CTL->>CTL: validate auth chain (provider key + integrationKey)
  CTL->>CTL: System-connected guard (else 409 system_not_connected)
  CTL->>CTL: validate amount / items / event_type
  CTL->>SVC: createPOSCheckoutSession
  SVC->>WAPIO: generatePurchaseQR
  WAPIO-->>SVC: { whatsapp_deep_link }
  SVC->>RDL: create link
  RDL-->>SVC: redirectlinks (code / short_url)
  SVC->>SVC: transition sessions -> QR_GENERATED
  SVC-->>CTL: session (with short_url)
  CTL-->>System: { qr_link, purchase_reference, integration_key }
  System->>System: render QR from qr_link + print on receipt
  CUST->>CUST: scans QR
  CUST->>WHATS: opens WhatsApp deep link
  WHATS->>ORCH: POST /webhooks/wapio/customer-verification
  ORCH->>ING: POST /integrations/purchases
  ING->>ING: InternalEvent + processEvent
  ING-->>CUST: points awarded (loyaltyLedger / CustomerOutletPoints)
```

## Implementation notes

- **Send `payload.order_id` on every request** — it costs nothing and makes retry semantics exact. Without it, every request creates a new session.
- **Never block the sale** — loyalty QR failure must never block or fail the sale. Always print the receipt.
- **No customer phone on this endpoint** — the endpoint is phone-less. Customer identity is resolved later during the WhatsApp claim flow.
- **Integration key in request body** — the store's integration key (`integrationKey`) is sent in the request body and validated against the store resolved from the API key's `store_id` scope. It is echoed back in the response as `data.integration_key`.
