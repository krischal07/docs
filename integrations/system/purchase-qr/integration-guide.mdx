The endpoint is authenticated with the **provider API key** (`Authorization: Bearer <provider_api_key>`, which confirms the System vendor). The store is resolved from the API key's `store_id` scope. The store's **integration key travels in the request body** (`integrationKey`), not a header. No `webhook_token` or `X-Integration-Key` header is used on this endpoint.

## Example curl (success)

```bash
curl -X POST https://server.samparka.co/integrations/system/{provider}/purchase-qr \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <provider_api_key>" \
  -d '{
    "integrationKey": "your_store_integration_key",
    "payload": {
      "event_type": "order.completed",
      "order_id": "ORDER-1001",
      "created_at": "2026-06-08T10:15:00.000Z",
      "amount": 1250,
      "currency": "NPR",
      "items": [
        { "name": "Cappuccino", "qty": 1, "price": 850 },
        { "name": "Croissant", "qty": 2, "price": 200 }
      ]
    }
  }'
```

### 200 — System connected + active communication provider → real Wapio QR

```
HTTP 200
{
  "success": true,
  "message": "Purchase QR ready",
  "data": {
    "qr_link": "https://samparka.co/r/xKd93k",
    "purchase_reference": "sysqr:restrox:6a9e80a4...:ORDER-1001",
    "amount": 1250,
    "currency": "NPR",
    "status": "QR_GENERATED",
    "expires_at": "2026-08-26T12:12:04.000Z",
    "integration_key": "your_store_integration_key"
  }
}
```

### 400 — Bad request (validation failure)

```
HTTP 400
{
  "success": false,
  "message": "Invalid purchase QR request",
  "errors": { "code": "purchase_qr_validation_failed" }
}
```

### 401 — Missing/mismatched integration key or invalid provider key

```
HTTP 401
{
  "success": false,
  "message": "Invalid provider key or integration key mismatch"
}
```

### 403 — Store scope required or unsupported capability

```
HTTP 403
{
  "success": false,
  "message": "API key must be bound to a store"
}
```

or

```
HTTP 403
{
  "success": false,
  "message": "Provider does not have submitPurchase capability enabled"
}
```

### 404 — Unknown provider or integration not found

```
HTTP 404
{
  "success": false,
  "message": "Unknown provider"
}
```

### 409 — System integration not connected

```
HTTP 409
{
  "success": false,
  "message": "{provider} is not connected for this store",
  "errors": { "code": "system_not_connected", "status": "CREATED" }
}
```

### 422 — No active communication provider

```
HTTP 422
{
  "success": false,
  "message": "No active connected communication provider is configured"
}
```

## Behavior matrix

The endpoint only issues a QR when the System integration is connected **and** an active communication provider exists.

| System | WhatsApp/Wapio | Result |
|---|---|---|
| Not connected | anything | `409 system_not_connected` — no QR, no session |
| Connected | not connected | `422 no active connected communication provider` — no QR, no session |
| Connected | connected | `200` real Wapio QR |

## Design choices

| Choice | Rationale |
|---|---|
| Auth via **provider API key (Bearer) with store scope** | The Bearer key (`spkp_…`) confirms the System vendor; the key's `store_id` scope resolves the store and integration. Provider key `slug` must match the route `:provider`. The API key must be bound to a store — a key without a store scope fails with `403 store_scope_required`. |
| **Integration key in request body** | The store's integration key (`integrationKey`) is sent in the request body and validated against the store resolved from the API key's `store_id` scope. This replaces the previous `X-Integration-Key` header approach. The key is echoed back in the response as `data.integration_key`. |
| **Webhook-style envelope body** | The request uses an envelope format with `integrationKey` at the top level and sale details wrapped in `payload`. This aligns with webhook payload conventions. |
| **Required `event_type: "order.completed"`** | The payload must include `event_type` set to `"order.completed"`. Other values → `400`. |
| **Recommended `payload.order_id` for idempotency** | When provided (max 100 chars), `order_id` serves as the idempotency key with format `sysqr:{provider}:{integrationId}:{orderId}`. May also be sent as `Idempotency-Key` header. |
| **Items are required at creation** (400) | The System must send product items so the QR session has the bill details needed for loyalty attribution. Σ(items) must equal amount ±0.01. |
| **`currency` defaults to `NPR`** | System payloads may omit currency; dashboard uses 3-letter codes, Nepal is the operating market. Explicit value overrides. |
| **System must be genuinely connected** | The endpoint refuses with `409 system_not_connected` unless the integration status is `CONNECTED`/`ACTIVE` — matches the dashboard's notion of "connected". A `CREATED`/`DISCONNECTED` integration can't issue checkouts. |
| **Requires an active communication provider** | If the System is connected but no WhatsApp/Wapio communication provider is active, session creation aborts with `422` (`no active connected communication provider`) — no QR is issued. There is deliberately **no fallback** deep-link. |
| **Golden rule: never block the sale** | Loyalty QR failure must never block or fail the sale. Always print the receipt. QR generation failures are non-fatal. |

## File map

| File | Purpose |
|---|---|
| `src/integrations/system/purchaseQrController.js` | Envelope parsing/validation (`event_type`, `order_id`, `created_at`); integration key validated from request body; richer session metadata |
| `src/integrations/system/integrationAuthMiddleware.js` | Integration resolved by API key's `store_id` scope (no integration key in header) |
| `src/integrations/system/routes.js` | Route wiring |
| `src/purchaseSessions/service/PurchaseSessionService.js` | `createPOSCheckoutSession()` — System entry point that routes through the normal `createSession()` / Wapio pipeline |
| `src/purchaseSessions/utils/processingStatus.js` | Reused. `getProcessingStatus()` drives response codes |
| `__tests__/integrations/system.purchase-qr.test.js` | 32 cases (see Testing page) |

## Implementation notes

- **Send `payload.order_id` on every request** — it costs nothing and makes retry semantics exact. Without it, every request creates a new session.
- **Never block the sale** — loyalty QR failure must never block or fail the sale. Always print the receipt.
- **No customer phone on this endpoint** — the endpoint is phone-less. Customer identity is resolved later during the WhatsApp claim flow.
