## Import Instructions

<Steps>
  <Step title="Download The JSON File">
    Save the raw `postman-collection.json` file directly from this documentation portal.
  </Step>
  <Step title="Import Into Postman">
    In Postman, choose import and select the unchanged collection file.
  </Step>
  <Step title="Fill Environment Values">
    Set `baseUrl`, `providerApiKey`, `integrationKey`, `expectedLocationId`, `expectedLocationName`, `customerPhone`, and `webhookToken`.
  </Step>
</Steps>

## Recommended Testing Order

<Steps>
  <Step title="Connect Location">
    Connect the external location using your integration key and confirm the response returns `CONNECTED` and a webhook token.
  </Step>

</Steps>

# Postman Collection — Purchase QR

The collection's `Purchase QR` section lets you exercise the QR checkout from the System terminal. It calls the purchase QR endpoint and sends the cash-sale details:

```json
{
  "amount": 1250,
  "currency": "NPR",
  "items": [
    { "name": "Cappuccino", "qty": 1, "price": 850 }
  ]
}
```

- **Endpoint** — `POST {{baseUrl}}/integrations/system/{{provider}}/purchase-qr`
- **Auth** — `Authorization: Bearer <provider_api_key>` (store resolved from API key scope)
- **Response** — `200` with `qr_link`, `purchase_reference`, `amount`, `currency`, `status: QR_GENERATED`, and `integration_key`

## Recommended Testing Order

<Steps>
  <Step title="Connect Location">
    Connect the external location using your integration key and confirm the response returns `CONNECTED`.
  </Step>
  <Step title="Send Purchase QR Request">
    Send a valid purchase QR request and confirm the response returns `QR_GENERATED` with a scannable `qr_link`.
  </Step>
  <Step title="Verify Idempotency">
    Resend the same request and confirm the same QR is returned (200).
  </Step>
  <Step title="Verify Failure Cases">
    Confirm validation failure (`400`), System-not-connected (`409`), and no-comm-provider (`422`) paths.
  </Step>
</Steps>
